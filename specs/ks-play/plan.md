# Plan: ks-play

Written by the planning pass from `spec.md`. Each build pass takes the first unchecked task, ticks it when every check passes, and adds a note beneath it. A failed attempt is recorded as a note; three failed attempts on one task mean the loop writes `BLOCKED.md`.

Requirements 1 to 11 (the messages, and unloading and `DecodeEnded` in the engine and supervisor) were built interactively in steps 6a and 6b. The loop builds requirements 12 to 33: `ks::client` (`src/client/`) and `ks-play` (`src/apps/play/`). The public headers, the CMake targets, and stub bodies already exist (commit ac1029a). Keep the headers' API as it is: the acceptance tests compile against it. Private helpers may be added in new, non-public headers or in anonymous namespaces.

Unit tests for the new code go in `tests/client/` (`ks_client_tests`) and `tests/play_app/` (`ks_play_app_tests`), registered with `ks_add_test()` in `tests/CMakeLists.txt` (not protected). Unit tests must not start `kool_spin`, so they run inside the loop's sandbox.

## Decisions

- **Signals without handlers (task 10).** Requirement 29 asks for exits 130 and 143 within 1 s even while `load` waits up to 30 s for a probe, and `ks::client`'s waits don't watch for signals. A signal handler would be the obvious answer, but under RealtimeSanitizer a handler that interrupts `KS_NONBLOCKING` code (the seqlock reads in `snapshot()`, `RingProducer::try_push()`) is reported (`CLAUDE.md`). So all threads block the signals, the work runs on a second thread, and the main thread `sigwait()`s, as `ks-engine` takes its stop signals. `sigtimedwait()` and `ppoll()` aren't on macOS, so they're avoided. `std::_Exit()` closes the connection by ending the process, which satisfies "closing its connection".
- **Detecting a lost `kool_spin` in `--watch`** (task 9): the state segment stays mapped after the engine dies, so a snapshot alone can't tell. A `ping()` each interval can, and costs a round trip per interval of at least 50 ms.
- **`NotReachable`:** every failure of `connect_to_supervisor()` (no socket, nothing listening, the wrong owner, and `EPERM` in the sandbox) maps to `NotReachable`, so `ks-play` exits 3 for all of them, as requirement 27 lists.
- **The `DecodeEnded` queue** keeps at most 64; when it's full, the oldest is dropped (requirement 19 says "up to 64" and doesn't say which to drop; the newest is likelier to be the one a caller waits for).
- **Relative paths** are made absolute lexically (`(cwd / path).lexically_normal()`), so `parse()` stays free of the file system, as its header promises and the fuzz target needs. `lexically_normal()` removes `..` lexically, which matches "without following symbolic links".
- **Request ID mismatch:** a reply whose request ID matches no outstanding request is ignored (requirement 19); requests are made one at a time, so there's only ever one outstanding.
