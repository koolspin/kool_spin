## Decisions

- **One snapshot read per engine:** requirement 12 says an engine built with a state block calls `read_snapshot()` once, with either constructor. The state-block constructor reads it and keeps the result in a private member, and the resuming constructor uses that copy rather than reading again.
- **Mixer settings through setters:** `Mixer` has no bulk setter, and adding one would change a public header the spec doesn't list. Every value in a valid snapshot is in range, so the setters' clamping leaves it unchanged and `settings()` equals the snapshot's. The mixer smooths gains with a 1 ms time constant, which settles long before the 50 ms fade ends, so the "No gap" criterion isn't affected. If a pass finds a setter that does change a valid value, it records it here.
- **The resumed reference lives in the deck's first place:** "as if `load()` had given one" means the same bookkeeping `apply_load()` does. With the constructor running before any block, the deck's places are all free, so the first is used.
- **Shared encoders in an internal header:** `encode()` and `rendered()` must encode mixer fields identically (requirement 3: "encoded as in `MixerState`"), so they share one implementation rather than two copies.
- **Fuzz target timing:** requirement 19's 200,000 runs are set in the protected `CMakeLists.txt`. If the target is too slow under `fuzz`, the fix is making `validate()` cheaper, not the run count.
