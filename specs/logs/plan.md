# Plan: logs

Written by the planning pass from `spec.md`. Each build pass takes the first unchecked task, ticks it when every check passes, and adds a note beneath it. A failed attempt is recorded as a note; three failed attempts on one task mean the loop writes `BLOCKED.md`.

Every task leaves `debug`, `asan`, `rtsan` and `tools/lint.sh` clean, apart from acceptance tests for later tasks (`ctest -LE acceptance` on this branch until the last task). The API and stubs already exist (`src/ipc/log.cpp`, `src/apps/supervisor/log_file.cpp`, `--log-fd` and `--log-dir` parsing); tasks replace stub bodies. No task touches a protected path. New `.cpp` files are added to `src/*/CMakeLists.txt`, which isn't protected.

## Decisions

- **Writer before formats.** Tasks 1 to 3 are pure library work with the acceptance tests directly checking them, so each turns tests green before any process is touched.
- **The engine before the supervisor.** The engine tests play the supervisor themselves, so task 4 can be verified without the supervisor changes in 5 to 7.
- **One report sink per process.** Both processes already funnel every message through one `report()` function; the plan changes that function to take a level and choose the destination, rather than editing each call site's output logic.
- **Supervisor lines are `info` unless the spec's table says otherwise**, mapped by the table in requirement 15.
- **Timestamps for the supervisor's own lines** come from `steady_clock` read at the time of the event, formatted with the session's one `LogClock`.
- **The earlier steps' tests keep working** because the three protected helpers already pass `--log-dir` (spec decision 8); no test changes are needed.

## Learnings

(Filled in by build passes.)

- **Pass 1, the sandbox refuses the supervisor's socket.** In this pass's sandbox, 15 acceptance tests from earlier steps fail before any change: every "Supervisor: …" test that needs a listening supervisor, the five "Supervisor rings: …" tests, and three "Supervisor socket: …" tests. `kool_spin` reports `can't open the supervisor socket: Operation not permitted`, and `Listener` creation fails the same way in the socket-protocol tests. They fail identically before and after the pass, so they aren't regressions, but it means a pass can't verify here any logs test that starts `kool_spin` and connects a client (tasks 6 and 7, and the finishing run of the whole suite). The maintainer may need to allow Unix-socket binding in the loop's sandbox, or check those tests outside it.
- **Pass 1, choices in the writer.** A line that isn't UTF-8 (more than three continuation bytes before the cut) is cut at `kLogTextSize` exactly; formatting escapes the bytes. A line that a corrupt ring refuses is counted in `dropped`, like one a full ring refuses. The unused part of a record's text is zeroed, so nothing from the writer's memory reaches the segment.
- **Pass 2, choices in the formats.** The spec leaves these open; each is the reading that keeps every line well-formed:
  - **Which time has to fit:** the local time, the one shown, must fall in the years 1970 to 9999. A UTC time in 1969 whose local time is in 1970 is shown.
  - **No `__int128`:** the conversion works in seconds and nanoseconds, and refuses a UTC offset beyond ±2 × the seconds to the year 10000 before adding it, so nothing overflows.
  - **Dates** come from `std::chrono::year_month_day`, which is arithmetic on the day count. `localtime_r` is called once, in `LogClock::now()`; if it fails, the offset is 0.
  - **`format_log_line()` with a level that isn't one** makes the invalid record's line.
  - **The header:** a clock whose time can't be shown gives `session started steady:<n>`; the offset's hours take more than two digits if they need them; the process name is escaped like a line's text.
  - **A backslash in the text is copied as it is,** as the spec says, so `\x41` typed in a line and an escaped byte can look alike.
- **Pass 3, choices in `LogFile`.**
  - **The limit warning** has the time of the line it replaces, so the file's times stay in order. `write()` returns false for that line: it wasn't written. Reaching the limit isn't an error, so `error()` stays empty.
  - **A line that ends exactly at the limit is written;** one byte more isn't. A limit that the header alone passes gives a file of the header and the warning.
  - **A partial write** (a full disk, a file-size limit) is followed by a write of the rest; if that fails, the file ends in part of a line, with no newline, and `error()` is set. The file is opened with `O_APPEND`.
  - **`LogFile` got a private member function,** `write_formatted()`, in `log_file.h`; the public API is unchanged.
  - **Testing a write error:** the unit test caps the file size with `RLIMIT_FSIZE`, with `SIGXFSZ` ignored, so `write()` fails with `EFBIG`. The cap is process-wide, so the test lifts it before it checks anything.
- **Task 4, choices in the engine's lines.**
  - **New lines without `--log-fd`:** the output lines and the refusals of an `Attach` or a `Detach` are new reports, and without `--log-fd` they go to standard error like the rest. The earlier steps' tests don't read the engine's standard error for them.
  - **Wording:** `output playing on a device at <rate> Hz, <n> channels`; `output freewheeling: no device opened` for the first line about the output, and `output freewheeling: the device was lost` after a playing line; `refused an Attach: <why>` and `refused a Detach: <why>`; `stopping: got a signal` or `stopping: the supervisor asked` (one line, where there were two: `got a signal`, then `stopping`).
  - **The attaching state isn't logged,** as the spec says: a device that returns and is dropped again before it plays adds no line.
  - **A starting failure** goes to standard error always, and to the log as an `error` once the log is open. A failure to open the log itself can only go to standard error.
  - **The sandbox's failing tests** are 16 before and after this pass, not 15: 5 "Supervisor rings: …", 8 "Supervisor: …", and 3 "Supervisor socket: …".
- **Pass 1, stray files.** `git status` in the sandbox shows untracked device nodes at the top of the worktree (`.bashrc`, `.gitconfig`, `.idea`, and others). They're the sandbox's placeholders: stage files by name, never with `git add -A`.
