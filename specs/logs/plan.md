# Plan: logs

Written by the planning pass from `spec.md`. Each build pass takes the first unchecked task, ticks it when every check passes, and adds a note beneath it. A failed attempt is recorded as a note; three failed attempts on one task mean the loop writes `BLOCKED.md`.

Every task leaves `debug`, `asan`, `rtsan` and `tools/lint.sh` clean, apart from acceptance tests for later tasks (`ctest -LE acceptance` on this branch until the last task). The API and stubs already exist (`src/ipc/log.cpp`, `src/apps/supervisor/log_file.cpp`, `--log-fd` and `--log-dir` parsing); tasks replace stub bodies. No task touches a protected path. New `.cpp` files are added to `src/*/CMakeLists.txt`, which isn't protected.

## Tasks

- [ ] 1. **Writer and reader.** In `src/ipc/log.cpp`, implement `LogWriter` (mutex, stamp with `steady_clock` ns, truncate at the last UTF-8 boundary or at a newline and set `kLogTruncated`, push through `RingProducer`, count drops in `segment.dropped`, write counts only) and `LogReader` (`next()`, `take_dropped()` with the lower-count corruption rule, `corrupt()`, never touching the segment once corrupt). Copy before use; range checks written so NaN-style surprises can't pass. (advances: "Log segments: layout", "Log writer: lines in order, from many threads", "a full ring drops lines and counts them", "long lines are truncated", "Log reader: a corrupt ring")
- [ ] 2. **Clock and line formats.** In `src/ipc/log.cpp` (split a `log_format.cpp` if it passes ~200 lines), implement `LogClock::now()` (steady ns, system ns, local UTC offset via `localtime_r`), a overflow-free steady→system→local conversion (use `__int128` or checked arithmetic; times outside years 1970–9999 become `steady:<n>`), a civil-date conversion done by hand (no locale or timezone lookups after `now()`), the escaping of control characters and invalid UTF-8 as `\xNN` (including U+0080–U+009F, overlong forms, surrogates, and values above U+10FFFF), `format_log_line`, `format_log_record` (truncation `…`, invalid-record warning) and `format_log_header` (`±HH:MM`, steady clock `s.nnnnnnnnn`). Handle the fixed-clock examples exactly, including rounding down to the microsecond. (advances: "Log lines: format", the fuzzing criterion `ks_log_record_fuzz`; run it briefly under the `fuzz` preset)
- [ ] 3. **`LogFile`.** In `src/apps/supervisor/log_file.cpp`, implement `create` (`O_CREAT|O_EXCL|O_WRONLY|O_CLOEXEC`, mode 0600, header written), both `write()` overloads (one `write()` call per line with the newline, retrying `EINTR` and short writes without splitting lines where possible), the size limit with its one final warning line (at most one line past the limit), and `error()` after a write failure. (advances: "Log files: the size limit")
- [ ] 4. **Engine logs through its segment.** In `src/apps/engine/run.cpp`: at the first starting step, check that `--log-fd` is open and make it close-on-exec; before taking the `engine` lock, map it read-write as `SegmentKind::Log` at `kLogLayoutVersion`, find the `LogSegment` with the mapping's own size, start a `LogWriter`; failure is a starting failure (to standard error, status 1). Route `report()` to the writer with levels per requirement 18 (give `report` a level parameter, and pick levels at each call site; starting failures go to both). Without `--log-fd`, nothing changes. Keep the phrases of requirement 19 (`ready`, `attached a ring in slot <n>`, `stopped`). Add `OutputController` control-thread accessors for the device's rate and channels if needed, and log `output playing` / `output freewheeling` after `start()` and each `poll()` when `state()` changes from the last logged state. A closed descriptor and a state-segment descriptor are refused before the lock. (advances: "Engine logs: through its segment", "a bad log descriptor", "a full ring never blocks it"; add an offline unit test for the output-state logging only if it isn't covered, per the offline-render rule)
- [ ] 5. **Log folder helpers.** New `src/apps/supervisor/log_dir.{h,cpp}` (standard library and POSIX only): the default folder (`XDG_STATE_HOME` absolute, else `$HOME/.local/state/kool_spin/logs`; macOS `$HOME/Library/Logs/kool_spin`; none without a usable `HOME`), recursive creation with mode 0700, session name `YYYY-MM-DD_HH-MM-SS_<pid>` from the `LogClock`, and pruning to the 9 newest session folders (sort by time in name then pid; delete only regular `.log` files, using `lstat`/`unlinkat` without following symlinks, then the folder if empty via `rmdir`; nothing else). Add a unit test in `tests/` (not `tests/acceptance`) registered with `ks_add_test()` in `tests/CMakeLists.txt` for the pruning and name parsing edge cases (symlinks, non-matching names, `.log` file at top level). (advances: "Logs: keeps the newest ten sessions", "Logs: the default folder", groundwork for "Logs: a session folder")
- [ ] 6. **Supervisor opens its logs and starts the engine with `--log-fd 5`.** In `src/apps/supervisor/run.cpp` and `spawn.cpp`: after the `supervisor` lock and before the `engine` lock check, read `LogClock::now()` once, create the folder, prune, create the session folder and `kool_spin.log`, create the engine's log segment next to the state segment (failure is a starting failure), pass it as descriptor 5 and add `--log-fd 5` to the engine arguments, create `ks-engine.log` just before spawning. Route `report()` through a single sink that writes to `kool_spin.log` with a level (and warnings and errors also to standard error as `kool_spin: <line>`; everything to standard error when there are no files). Assign levels to every existing report per requirement 15, keeping the existing standard-error lines the earlier specs require and the phrases of requirement 19 (`client '<name>' asked for a ring`, `opened a ring in slot <n>`, `refused client '<name>' a second ring`, `ks-engine was killed by signal <n>`). Add the engine-ended-unexpectedly report as `error`. `--help` and usage errors create no folder. Fall back per requirement 13 with one warning naming the cause and the `--log-dir` path; a failed `ks-engine.log` alone sends the engine's lines to standard error as `ks-engine: ...`. (advances: "Logs: a session folder", "Logs: shared timestamps" once task 7 lands, "Logs: without a log folder", "Logs: standard error gets kool_spin's warnings and errors", "Logs: the default folder")
- [ ] 7. **Draining the engine's ring.** In `src/apps/supervisor/run.cpp`: map the engine's log segment read-write, keep the descriptor and mapping until exit, build a `LogReader`; add `kLogDrainInterval` as the cap on the `poll` timeout while the engine runs (`poll_timeout`); drain after every `poll` return, and once more after the engine is reaped and before reporting how it ended. Write each record with `LogFile::write(record)` (or, without a file, to standard error as `ks-engine: <formatted text>`), warn in `ks-engine.log` when `take_dropped()` is above 0, and on a corrupt ring write an error to both files and stop reading. Also report a failed log file once (in `kool_spin.log` if it still works, and standard error). (advances: "Logs: shared timestamps", "Logs: the engine's last lines outlive it", "Logs: a session folder", "Logs: without a log folder")
- [ ] 8. **Cleanup and handoff.** Run the whole check set (`debug`, `asan`, `rtsan`, `tsan`, then `tools/lint.sh`), run `ks_log_record_fuzz` briefly under the `fuzz` preset, check every `[auto]` acceptance test passes with `ctest --preset debug -L acceptance`, then write `specs/logs/pr-description.md`, listing the `[manual]` device-events check as left for the maintainer, the protected test-helper changes already approved in the spec, and the macOS checks only CI can do. Don't edit `CLAUDE.md`'s Status section (protected); mention in the PR description that the maintainer should update it. (advances: all remaining, "The earlier steps' tests all still pass", "Every CI configuration")

## Decisions

- **Writer before formats.** Tasks 1 to 3 are pure library work with the acceptance tests directly checking them, so each turns tests green before any process is touched.
- **The engine before the supervisor.** The engine tests play the supervisor themselves, so task 4 can be verified without the supervisor changes in 5 to 7.
- **One report sink per process.** Both processes already funnel every message through one `report()` function; the plan changes that function to take a level and choose the destination, rather than editing each call site's output logic.
- **Supervisor lines are `info` unless the spec's table says otherwise**, mapped by the table in requirement 15.
- **Timestamps for the supervisor's own lines** come from `steady_clock` read at the time of the event, formatted with the session's one `LogClock`.
- **The earlier steps' tests keep working** because the three protected helpers already pass `--log-dir` (spec decision 8); no test changes are needed.
