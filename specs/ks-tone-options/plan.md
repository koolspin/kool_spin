- [ ] 3. **Frequency meter in `ks::dsp`.** Add `src/dsp/include/ks/dsp/frequency_meter.h` (header-only, like `sine_oscillator.h`): `class FrequencyMeter { explicit FrequencyMeter(double sample_rate) noexcept; void push(float sample) noexcept KS_NONBLOCKING; double frequency_hz() const noexcept KS_NONBLOCKING; }`. Method: detect upward zero crossings (`previous <= 0 && sample > 0`), interpolate each crossing's fractional sample position linearly, and keep the first crossing's position, the last crossing's position, and the crossing count. Frequency = `(count - 1) * sample_rate / (last - first)`, or 0 with fewer than two crossings. No allocation, no containers: a handful of scalars. Errors per crossing don't accumulate, so over 0.1 s or more this is far inside 0.1%. ## Decisions

- **Exit code for requirement 12.** The spec lists it among the usage errors (requirements 8-12, exit 2), and the device-number check (11), also discovered only once a backend is open, is tested with exit 2. So a frequency too high for the device is a usage error: exit 2, nothing plays.
- **`--list-devices` and other options.** "Other options are ignored" is read as: their values don't affect listing. The arguments are still parsed, so a malformed option (`--level loud`) is still a usage error with exit 2. This keeps one parser and makes typos visible.
- **`--backend` unchanged.** An unknown backend stays a runtime failure (exit 1) with today's message, since the spec puts any change to `--backend` out of scope.
- **Number syntax.** `std::from_chars` with `chars_format::fixed`, consuming the whole string, then a finite range check. This accepts `440`, `440.5`, `-12`, `.5`, and rejects `nan`, `inf`, `""`, `440x`, `1e3`, `+440`, and leading spaces. `.5` and `0.50` are accepted as decimals.
- **Unknown arguments** keep today's `ks-tone: unexpected argument '<arg>'` message and exit 2, but print only that one line, since usage errors are one line (requirement "Errors").
- **Measuring frequency.** Upward zero crossings with linear interpolation, first-to-last span. Zero crossings don't move during fades (the gain scales the sine), it needs no buffers, and its error doesn't grow with length. At 20 kHz and 48 kHz (2.4 samples per cycle) a single crossing's interpolation error is under a sample, which over 1 s is about 0.002%.
- **Peaks at the extremes.** At 48 kHz, 20, 440 (to 0.1 dB), 1000, and 20000 Hz all have samples at or very near the sine's crest, so the existing peak tracking already prints the requested level; no change is planned there.
- **Duration type.** The spec allows fractional seconds, so the duration is carried as `std::chrono::duration<double>` (or exact microseconds), not truncated to whole seconds.

## Learnings

- The existing non-acceptance tests `ks-tone.plays_on_null_backend` and `ks-tone.rejects_unknown_arguments` in `tests/CMakeLists.txt` check `ks-tone`'s output with regexes; keep them passing (requirement 16), adjusting them only where the spec changes the output.
